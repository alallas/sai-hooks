# sai-hooks 架构说明（技术版 · 通俗讲）

这份文档讲清楚两件事：**整个系统是怎么搭起来的**（大架构），和**每个关键决定背后的原因**（架构细节）。不用专业黑话，读到哪段不懂可以直接问。

---

## 一、一分钟看懂全貌

我们的目标是给 SAI2 加一个「液化」功能（把画好的线条像橡皮泥一样推来推去）。SAI 本身没有这个功能，也不提供插件接口，所以我们用了一个绕路的办法：

```
你双击启动 SAI
    │
    ▼
┌─────────────┐     ┌──────────────────────────────────────────┐
│  injector   │────▶│  SAI2 进程（sai2.exe）                    │
│  (注入器)    │ 把  │                                          │
│  独立小程序  │ DLL │  ┌───────────────────────────────┐       │
└─────────────┘ 塞进│  │  sai_hooks.dll（我们的插件）   │       │
                  │  │                               │       │
                  │  │  ┌─────────┐  ┌───────────┐  │       │
                  │  │  │液化窗口  │  │GPU 变形引擎 │  │       │
                  │  │  │(ImGui)  │  │(warp)     │  │       │
                  │  │  └─────────┘  └───────────┘  │       │
                  │  │  ┌───────────────────────┐   │       │
                  │  │  │SAI 内存读写/撤销/刷新  │   │       │
                  │  │  └───────────────────────┘   │       │
                  │  └───────────────────────────────┘       │
                  └──────────────────────────────────────────┘
```

**三个角色：**

| 角色 | 是什么 | 干什么 |
|---|---|---|
| **injector**（注入器） | 一个 30 行的小程序 | SAI 启动后，把我们的 DLL 塞进 SAI 的内存里，然后自己退出 |
| **sai_hooks.dll**（插件本体） | 一个大 DLL | 住进 SAI 进程里，负责所有事：窗口、变形、写回 |
| **SAI2** | 目标软件 | 被注入的对象，我们自己不改动它任何文件 |

为什么要「注入」而不是做个独立程序？因为液化要读写 SAI 画布里的像素——这些数据只在 SAI 的内存里，外部程序读不到（也读不准）。住进它的进程，才能摸到它的数据。

## 二、一次液化的完整旅程

你按 `Ctrl+Shift+X` 到点「确定」，中间发生了这些事：

```
① 拿像素      ② 复制一份到 GPU    ③ 你推着玩      ④ 把结果塞回去    ⑤ 告诉 SAI 刷新
```

### ① 快照（把画拿出来）

插件先问 SAI：「当前选中的图层，512×512 的画，像素给我一份」。

SAI 的像素不是一整块存的，而是**打碎成很多小块**（叫「瓦片」，一块 128×128 左右），散在内存各处。插件把这些瓦片一片片捡回来，拼成一张完整的图。选了多个图层就各拼一张。

> ⚠️ **铁律一：这件事必须让 SAI 自己干。**
> 插件是「客人」，直接翻 SAI 的内存容易翻崩（SAI 正在画，数据一半是变的）。所以插件给 SAI 主窗口发一条消息「麻烦你在你的线程里帮我取一下」，SAI 在自己的节奏里完成，稳。

### ② 上传到显卡（warp 引擎接管）

拼好的图从内存复制到显卡（GPU）上。之后所有变形计算都在显卡上做——显卡擅长这种海量像素计算，推一笔算一笔，60 帧不卡。

GPU 上建了几块「画布」：

- **快照图**：原图的副本，变形的参照基准
- **位移场**（两张，来回倒）：记录「每个像素往哪挪」。你推一笔，就往位移场里加一笔位移
- **冻结图**：你涂了「冻结」的地方，位移进不去（保护起来不变形）
- **预览图**：每次变形后，按位移场把原图重新采样一遍，就是你在窗口里看到的画面

### ③ 你在液化窗口里推线条

窗口里看到的预览，就是把「位移场」套在「快照图」上的结果。每笔下去：

- 变形笔刷 → 往位移场加位移
- 冻结笔刷 → 往冻结图涂保护色（涂过的地方位移失效）
- 解冻笔刷 → 把保护色擦掉

窗口里的 Ctrl+Z/Ctrl+Y 是插件自己的撤销栈（能记 16 笔），跟 SAI 的撤销无关——这时候 SAI 画布还没动过。

### ④ 写回（把变形后的画塞回 SAI）

点「确定」，插件把 GPU 上变形完成的图读回内存，写回 SAI 的图层。

写回有几个讲究：

- **整层重写，不是补丁**。早期版本只写「有内容的瓦片」，结果线条被推到空白处时，多出来的部分被丢掉了（边缘裁剪 bug）。现在逐个瓦片对比「变形结果 vs 原图」，有变化才写，凸起多少写多少。
- **必须生成所有缩略级别**（MIP）。SAI 为每个图层存了 6 级缩小版（缩小时显示用），只写最大那张的话，缩小时候看到的还是旧图。
- **多图层一次搞定**。选了好几个图层时，全部写完再统一收尾，SAI 里按一次 Ctrl+Z 能整体撤销，不会一层一层撤。
- **失败不死**。写回是最危险的一步（直接改 SAI 的数据），所以包了一层「安全气囊」：万一写崩了，插件自己跳车退出，SAI 进程保住不闪退（详见下面「架构细节」第 3 条）。

### ⑤ 刷新与撤销登记

写完了 SAI 还不知道。插件做两件事收尾：

1. **刷新三件套**：调 SAI 内部的三个重绘函数 + 给窗口发「重画」消息。少任何一件都可能出现「要缩放一下画布才看到新图」。
2. **登记撤销**：往 SAI 的撤销栈里放一条记录「这个图层被我改过」。这样你在 SAI 里按 Ctrl+Z，能撤销这次液化——这是正常软件该有的样子，也是开发中最难啃的一块（见踩坑文档）。

## 三、插件内部模块划分

`sai_hooks.dll` 不是一个巨型文件，按职责切成了 4 块：

### dllmain.cpp —— 总管 + 大门

- DLL 被塞进来时最先执行，负责登记热键、创建右下角「液化」按钮
- 收到热键/按钮消息 → 启动液化会话
- 快照和写回的**实际执行**也在这里（通过消息机制在 SAI 线程里跑，对应铁律一）
- 无画布时弹提示，而不是闷声失败

### liquefy.cpp —— 液化窗口（你看到的界面）

- 创建液化悬浮窗（嵌在 SAI 主窗口里的子窗口，跟随移动）
- ImGui 画界面：笔刷选择、参数滑条、撤销/重做、确定/取消
- 接收鼠标笔画，转发给 warp 引擎
- 会话的生命周期管理

### warp.cpp/.h —— GPU 变形引擎（干活的）

- D3D11 初始化和资源管理（上面说的那几块 GPU「画布」）
- 5 种变形笔刷 + 冻结/解冻的计算着色器
- 位移场的叠加、撤销栈的快照恢复
- 预览渲染和最终结果生成
- 特点：**不碰 SAI 任何东西**，纯粹在显卡的独立空间里算账。这块最干净，出问题好排查

### sai_core.h + imgui_dx11.cpp —— 基础设施

- `sai_core.h`：SAI 内部结构的「地图」（哪个地址是图层、哪个是撤销管理器），全部来自逆向实测，见 `docs/sai2-offsets.md`
- `imgui_dx11.cpp`：窗口显示辅助（DirectX 交换链管理）

## 四、架构细节（关键决定和原因）

### 1. 为什么快照/写回必须走 SAI 的线程？

SAI 是单线程画画的程序，它的数据结构没有做多线程保护。插件如果直接从自己的线程去读它的图层数据，恰好碰上 SAI 在改这块数据，就会读到一半新一半旧的垃圾，或者直接让 SAI 崩溃。

解决办法是 Windows 的消息机制：插件给 SAI 主窗口 `SendMessage` 发一条自定义消息，SAI 收到后在它自己的消息循环里处理——这时候 SAI 是空闲的，数据是稳定的。

**这条规则写出来只要一行，踩出来花了两天**（见踩坑文档）。

### 2. 崩溃保险：VEH 跳车

就算走了 SAI 线程，写回时还是有小概率踩雷（比如用户恰好在写回瞬间删了图层）。插件注册了一个「异常观察员」（VEH，Windows 的结构化异常处理），写回开始前先在安全位置插个旗子（setjmp），一旦发生内存访问错误，观察员把执行一把拽回旗子处，写回宣告失败，但 **SAI 进程活着**。

代价：写回的失败状态要处理好，不能让 SAI 以为写成功了。

### 3. 为什么液化窗口是 SAI 的子窗口？

早期版本是独立悬浮窗，有两个问题：会在任务栏占一个位置；SAI 最小化时它还在。改成 SAI 主窗口的子窗口后，SAI 动它跟着动，SAI 最小化它一起消失。

副作用：SAI 会把不认识的儿子窗口藏起来或压在底下，所以有个 2 秒一次的定时巡逻，把液化按钮和窗口重新置顶。

### 4. 为什么撤销栈在 GPU 上还要再做一份？

窗口里的 Ctrl+Z 和 SAI 里的 Ctrl+Z 是两套：

- 窗口里的：改的是**位移场**，秒回，不涉及 SAI 数据
- SAI 里的：改的是**像素本身**，走 SAI 的撤销系统

混淆这两套会出很奇怪的 bug（推了一下撤销，线条回去了但预览没变）。

### 5. 像素量程的换算（0x4000 → 0xFFFF）

SAI 存像素用的是「15 位满量程」（最大值 0x4000 = 16384），显卡常用 16 位（0xFFFF）。快照上传时统一放大 4 倍，写回时再除回来。这个换算在 warp 引擎里一处做，别处不用管。

## 五、代码地图（改哪里找哪里）

| 要改什么 | 去哪个文件 |
|---|---|
| 界面布局、加按钮、改中文标签 | `liquefy.cpp` 的 `Run()` 函数，UI 段一目了然 |
| 笔刷手感（推的力度、软硬） | `warp.cpp` 的 `psSplat` 着色器 + `dab()` 的参数传递 |
| 冻结/解冻行为 | `warp.cpp` 的 `psFreeze` 着色器 |
| 写回逻辑、撤销分组 | `dllmain.cpp` 的 `WritebackLayersImpl` |
| SAI 结构偏移（版本升级后失效） | `sai_core.h` + `docs/sai2-offsets.md` |
| 热键、启动按钮 | `dllmain.cpp` 的 `placeLauncher` 和初始化段 |
| 构建配置 | `tools/build/build.py` |

## 六、数据流总结（一图流）

```
SAI 图层瓦片 ──①快照(经SAI线程)──▶ 内存整图 ──②上传──▶ GPU 快照图
                                                            │
你的鼠标笔画 ──▶ liquefy.cpp ──▶ warp dab() ──▶ GPU 位移场 ◀┤
                                                            │ ③预览: 快照+位移场重采样
                                              液化窗口显示 ◀┘
                                                            │
点确定: GPU 结果读回 ──④写回(经SAI线程+跳车保险)──▶ SAI 图层瓦片
                                                            │
                                              ⑤刷新三件套 + 撤销登记 ──▶ SAI 界面更新
```

### 初步结论

- **编译器特征**：`.code` + `.shared` + 小写 `text`/`data` 节区组合是 Delphi（Embarcadero）链接器的典型特征。SAI 历代均为 Delphi 开发，逆向时可按 Delphi 对象布局（对象头含 VMT 指针）假设数据结构。
- **渲染管线**：导入表中无 `d3d*.dll` / `opengl32.dll` / `d2d1.dll` / `gdiplus.dll`，仅有 `gdi32.dll` + `user32.dll` → SAI2 画布为 **GDI/CPU 软件渲染**（DIB 位图 + BitBlt 类路径）。
  - 对应 PRD 风险 R4：无需挂钩 D3D 渲染管线，插件独立悬浮窗方案可直接落地。
- **数位板输入**：WinTab API（`wintab` / `WTInfo` 字符串命中），标准数位板接入方式。
- 无加壳迹象（节区命名规整、可读字符串丰富）。

## 1. 图层结构（进行中）

### 1.1 已定位：像素缓冲区分配链路 ⭐

**FUN_1401c2590（0x1401c2590）—— 像素缓冲描述对象分配入口**

- 经 SAI 统一堆分配器 `FUN_1401a1b30(size)` 分配 **0x58 字节描述对象**
- 已知字段：`+0x02` type（short，1=DIB/2=兼容位图）、`+0x06` bpp（byte）、`+0x08/+0x0C` 宽/高（int）
- 内部按 `stride = ((bpp>>3)*width + 3) & ~3` 计算 DIB 行距
- **17 个调用者**（`.rea/decomp/functions/` 内 grep `1401c2590` 可得完整列表）：图层创建、画布尺寸变更等场景都经此入口
- 签名特征：分配 0x58 对象 + stride 计算指令序列，适合作特征码

**FUN_1401c2450（0x1401c2450）—— 描述对象 → GDI 位图实例化**

- `param_1` = 上层传入的描述结构；`param_1+0x28` 接收新建的 **0x30 字节 GDI 包装对象**
- GDI 包装对象字段：`+0x00` HDC（CreateCompatibleDC）、`+0x10` HBITMAP、`+0x18` 旧位图、`+0x28` 调色板
- type==1 时：`CreateDIBSection(hdc, BITMAPINFO*(param_1+0x30), 0, &bits, 0, 0)`，**bits 指针写回 param_1+0x18**
- type==2 时：`CreateCompatibleBitmap(hdc, w(param_1+8), h(param_1+0xc))`
- → **param_1 即图层像素缓冲宿主对象，+0x18 处可直接拿到像素首地址**

**统一堆分配器：FUN_1401a1b30（0x1401a1b30）** — SAI 所有对象/缓冲经此分配，插件侧 hook 此函数可监控一切内存活动。

- **表A（汉化/当前语言）**：0x14025d770 起，1683 条记录

## 4. 撤销栈（2026-11-03 逆向 + 运行时实证，对应风险 R1）

### 4.1 撤销管理器与容器链

- `O = *(app+0x168)` = 撤销管理器。`O+0x10` = 历史链头（最旧容器），`O+0x18` = 链尾（最新容器）。
  容器是侵入式链表节点：容器 `+0x00` = next（更新）容器；`O+0xa0` = **当前开放分组容器**（空闲时为 0，
  只在分组生命周期内非零——曾误判为"实测恒 0 不可用"）。
- 容器 = 0x200B 对象：内嵌记录链表 {head=+0x50, tail=+0x58, count=+0x60}；
  记录节点 `+0x00` = 更新链接、`+0x08` = 更旧链接；记录 = 0x180B（SAI 分配器 FUN_1401a2040 体系）。
- 笔画记录 type=1：`+0x54` = layer id，`+0x10` = 笔画包围盒 rect，`+0xa0` = 图层 type(4)、
  `+0xa4` = layer id，`+0xa8` = 0x81800000 类 before/after 镜像 scratch（`+0xd8/+0xe0` = 0x6000 尺寸）。
- 类型 6/7 记录 = 文档级操作（建画布等），与像素无关。

### 4.3 ⚠️ 线程模型：外部线程必崩，必须跑在 SAI UI 线程

- `FUN_1401a6510(callback, arg, ...)` 是 SAI 的「引擎线程回调投递」：把回调写进
  `*(TLS+0x3630)` 的线程私有队列再 `SetEvent`。**外部线程的该 TLS 为 NULL → 空指针崩溃**
  （2026-11-03 两次实录：FUN_140079510、FUN_14007e280、FUN_140040b40 内部都走这个投递）。
- **正解（已验证）**：注入 DLL 子类化 SAI 主窗（`GWLP_WNDPROC`），用
  `RegisterWindowMessage("KIMI_SAIHOOKS_CMD") + SendMessage` 让 **SAI 的 UI 线程**自己执行序列，
  原版函数全部安全。这套消息通道就是 P2 插件化的 IPC 骨架。源码 `src/sai_undo/dllmain_v10.cpp`，
  发送端 `tools/deploy/sai_send.py`。
- 注意 `FUN_140043360` 返回的是平面【待处理脏矩形】且随捕获消费（滤镜流程专用），
  外部写入场景不要用它的输出，rect 自己算。

### 4.4 平面双数组（2026-11-03 实证，⚠️ 语义尚未完全解码）

同一平面（layer+0xf8 → plane0）存在两套 16 行瓦片数组：

| 数组 | 标志 | 页指针 | 角色 |
|---|---|---|---|
| `+0x68 / +0x78` | 0x40B 行记录 | 8×qword | 撤销捕获(FUN_140075c70)从这里读；捕获条件 `(flag & 0x10)==0 && (flag & 0xc)!=0`（0xa4 满足） |
| `+0x38 / +0x40` | 0x40B 行记录 | 16×qword | 屏幕显示读这里；P1-m3 直接写这里用户可见 |

- 健康笔画曾观测：master 0xa4+有页 / cache 仅有标志；另一时段观测：两边都 0x01、页只在 cache。
  **0xa4 vs 0x01 的翻转条件未定位**（疑似与笔刷/合成周期/视图有关，待查）。
- MIP1..5 的页在 cache 组（+0x38/+0x40）；mip0 主缓冲在 +0x68/+0x78。
- MIP 重建公式：本级 (gx,gy) ← 上一级 (2gx,2gy),(2gx+1,2gy),(2gx,2gy+1),(2gx+1,2gy+1)，
  逐级 pavgw 精度 `(a+b+1)>>1`。**坐标必须是上一级空间**（v10 曾错写 `gx<<k`）。

## 5. 瓦片像素格式（2026-11-02/03 实证，P1-m2）

静态分析曾误判「瓦片 0x200B/16×16」，实测纠正：

- **画布尺寸**: `app+0x250` = 宽, `app+0x254` = 高（当前文档 512x512；±100000 的 `app+0x258..0x264` 是理论坐标空间，勿混淆）
- **像素 = 8 字节 = 4×u16 通道，BGRA 顺序，预乘 alpha，满量程 0x4000**
  （受控写回实验实证，2026-11-03：DLL 写 c0=0x4000 -> 快照渲染为蓝、SAI 画布同样显示蓝，
  写 c2=0x4000 -> 红；预乘证据 c==a 逐位相等。
  教训：用户边画边读会产生伪证，格式判定必须用受控写入）
- **瓦片页 = 32×32 像素 × 8B = 0x2000B**，堆页 8KB 对齐（指针步长 0x2000 实证）
- **FUN_14017fb40 = MIP 2×2 盒式降采样**（SSE2 pavgw），FUN_1401d98c5 = u64 行填充——证实 MIP 链逐级 1/2
- **平面行数组布局**（plane+0x38 / +0x40，双数组并行）：
  - `平面+0x38` → 行数组，行 y → **0x40B 标志记录**（前 32 字节，每字节 = 该列瓦片状态，0=空、1=有页）
  - `平面+0x40` → 行数组，行 y → **0x80B 页指针记录**（16 个 qword）
  - 行记录按 y 连续分配，标志/页记录分别来自两个池（0x38f0400 区 0x40 步长 / 0x3243xxx 区 0x80 步长），**指针有效不等于本平面所有行**（池是连续的，需结合标志 + 8KB 对齐页验证）
- 图层 `+0xf8[0..5]` = 6 级 MIP 链（每级 0x200B 平面对象内嵌数组）：plane[1] 内容行 = plane[0] 行号/2 已验证
- 快照解码器 `tools/reverse/sai_snapshot.py` 已可用（笔画/铅笔线/柔边笔迹形状全部正确）
- **预乘合成到白底**: out8 = (c16 + (0x4000 - a16)) * 255 / 0x4000（灰度笔画 68,68,68 等实测逐点吻合）
- 图层行标志数组有双份（+0x38 与 +0x50，内容互为镜像），行记录池在多个平面间连续排布，
  遍历时必须以「页指针 8KB 对齐且非空」为准，行数以上限 16（当前画布 512/32）为界

## 7. 显示链路与撤销栈完整结论（2026-11-03 下午，bisect13–bisect20，PID 33220→21280）

### 7.1 显示链路（已实证，最终答案）

**屏幕合成只读每级 MIP 平面的 +0x40 行表（视图缓存），不读 +0x70/+0x78。**
- +0x38 = 每瓦片 1 字节的缓存标志 cf，**cf=0x01 时缓存有效**；cf=0xa4 等 bit0=0 一律不显示
- 活笔画/原生滤镜后的瓦片：**f=0x01, w=c=同一页, p=0, cf=0x01**（c 别名指向工作页）
- SAI 撤销执行器对 f=01 瓦片：分配新页→写入恢复像素→**w 和 c 一起指向新页**（保持 c==w），显示自动正确
- 缩放读哪级：≥59.4% 读 P0 的 +0x40；≤50% 读 P1+（v12 提升只动 P0，故小 zoom 笔画仍在）
- 外部写入要可见：写 w 页（或确保 c 别名到要显示的页）+ cf=01 + 触发重绘
  （FUN_140020ed0(app)+FUN_140022920(app)+RedrawWindow）
- **必须持锁**（FUN_1400c900 / FUN_1400c920 对）再改瓦片结构，否则引擎线程并发竞争
  （症状：bisect15 双瓦片只显示一个；持锁后 bisect17 六瓦片全显示）

### 7.2 FUN_140074690 标志语义（读反编译确认）

- bit0(0x01)=+0x70 工作页在；bit1(0x02)=+0x70 槽非空；bit2(0x04)=+0x78 提交页在
- bit5(0x20)=脏（提升/捕获时置位）；bit7(0x80)=常态位（返回时恒置）
- 提升（param4=0,param5=0）：w→p 搬家，f 变为 0xa4（旧 0x01 情形），**0x20 脏位置位、c 缓存随后被释放**
- 撤销捕获 FUN_140075c70 是写时复制：只处理 `(f&0x10)==0 && (f&0xc)!=0` 的瓦片
  （旧页进记录、槽位换新副本、f|=0x10），**f=01 瓦片整体跳过**

### 7.3 撤销记录生命周期（读反编译 + 实测）

- FUN_14002ebd0(rec, app, layer, rectbuf) = **只登记脏矩形**到 app+0xc7c / +0xb50（app+0xa30 |= 0xfff），
  不拷贝像素；rectbuf 为 {x0,y0,x1,y1}，与 plane0 全幅求交
- FUN_14002eca0(rec, app, layer) = 真捕获：FUN_14007e280 分配三套记录页并
  **经 FUN_1401a6510 投到引擎线程**跑 FUN_140075c70（COW），rec+0x5c 1→2→3
- 分组：c900 进锁 → 02e880(app,0x48,1) 起点（建分组容器挂 O+0xa0）→ 02de30(app,layer,type) 建记录
  → 02ebd0 前态 → [写像素] → 02eca0 后态 → 25ac0(app) → 036620(app,layer_id) 收尾（链接入历史链
  FUN_140001000，清 O+0xa0）→ c920 出锁
- **02de30 第三参 type=2 的记录对 f=01 瓦片捕获为空**（bisect20 实测：undo 无效果）；
  a4 瓦片可捕获（bisect18）但撤销执行后显示不刷新（c 别名不被执行器维护）

### 7.4 原生基准（新画布实测，亮度/对比度滤镜）

- 滤镜提交后瓦片仍为 f=01 w=c=页（**滤镜流程不提升**）；撤销滤镜后 w/c 全部换成新页（像素级恢复）

### 7.6 f=01 捕获路径已定位：COW 方案，m4 闭环 ✅（2026-11-03 晚，bisect21/24）

**根因**：f=01 瓦片被 FUN_140075c70 整体跳过的原因是**瓦片尚未提升**。原生滤镜

3. 02de30(app, layer, 2) 建 type-2 记录
